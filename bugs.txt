Your corpus profiler can say:

```text table_count = 0
```

for a page that visibly contains a table in the scanned image.

So don't use:

```text table_count
```

as “does this document have a table?”

---

## 72. [✓] “visual complexity” is not actually visual complexity

Current heuristic:

```python
len(lines) > 5 or len(rects) > 3
```

This measures PDF vector geometry.

It does not measure actual visual complexity of scanned pages.

---

## 73. [✓] Scan detection is heuristic and can misclassify pages

Current:

```text images > 0 and text < 20
```

means:

```text likely scanned
```

but images inside digital PDFs don't imply scans.

Likewise scanned pages may contain OCR/native text.

This isn't a crash but the metadata semantics should not be treated as ground truth.

---

## 74. [✓] One page profiling failure marks the whole document as error

`profile_document()` has one outer try/except.

If:

```text page.find_tables()
```

throws for one page:

```text entire document → processing_status = error
```

Page-level fault isolation is better.

# The most important overall conclusion

The project is now **much closer**, but the biggest remaining problem is no longer “one obvious bug.”

It's **system consistency**.

Right now you still have:

```text
RAW PDF
   ↓
processed text/image
   ↓
index
   ↓
retrieval
   ↓
reranker
   ↓
generation
   ↓
frontend
   ↓
evaluation
```

where several stages can still disagree about:

```text
which model was used
which evidence was used
which score means what
which page is selected
which metadata is authoritative
which pipeline is actually being evaluated
```

The **single most dangerous inconsistency currently is the ColPali saved index vs ColQwen2 configured model**.

The **single biggest algorithmic weakness is that “Hybrid Reranked” is still not a true multimodal reranker**.

The **single biggest UI/data problem is that the frontend hardcodes incorrect document metadata and fake telemetry**.

The **single biggest security problem is the exposed API key**.

And the **single biggest evaluation problem is that the saved benchmark is not guaranteed to represent the current code/configuration**.

I would **not call this final yet**. But unlike earlier versions, the remaining work is now very clearly identifiable and mostly concentrated in these consistency/evaluation/reranking layers.
